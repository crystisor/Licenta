# Project: AI Video Generator Mobile App

## Overview
Mobile application where the user enters a text prompt, which is processed through a Stable Diffusion pipeline to generate an image, then animated into a video using an image-to-video pipeline. This is a university thesis project (Licenta).

## Architecture

### Frontend — Expo (React Native)
- Located in `frontend/`
- Single-screen app with a text input for the prompt and a display area for the generated video
- Communicates with the Python backend via REST API
- Tech: Expo, React Native, TypeScript

### Backend — Python
- Located in `backend/`
- REST API server (FastAPI) that receives prompts and returns generated videos
- All AI pipelines are implemented in pure Python using diffusers/torch — **no ComfyUI runtime or API calls**
- Serves generated media to the frontend

### Pipelines — Python
- Located in `backend/pipelines/`
- **Text-to-Image pipeline**: SDXL (JuggernautXL Ragnarok checkpoint), reimplemented from ComfyUI node graph into pure Python (using `diffusers`, `torch`, `safetensors`)
- **Image-to-Video pipeline**: Wan 2.2 I2V (14B) — takes the generated image and a motion prompt, produces a short video. Uses LightX2V 4-step LoRAs for accelerated inference

## Key Constraints
- **No ComfyUI dependency**: The ComfyUI workflow is reference-only. All nodes (checkpoint loader, CLIP text encode, KSampler, VAE decode, etc.) must be coded as native Python using HuggingFace diffusers or raw torch
- **Single GPU inference**: Runs on a local NVIDIA GPU
- **Models stored locally**: Model weights are in `/home/rheinsystems1/Desktop/AI/models/`

## Text-to-Image Pipeline (from ComfyUI workflow)
Reimplemented as Python code in `backend/pipelines/text_to_image.py`:

### Nodes
1. **Load Checkpoint** — Load `juggernautXL_ragnarokBy.safetensors` (SDXL) → returns model, clip, vae
2. **CLIP Text Encode (positive)** — Encode the user's prompt into conditioning
3. **CLIP Text Encode (negative)** — Encode negative prompt: `"cartoon, deformed"`
4. **Empty Latent Image** — Create empty latent tensor (832x1216, batch_size 10)
5. **KSampler** — Run the diffusion sampling loop
6. **VAE Decode** — Decode latents to pixel-space images
7. **Preview Image** — Return/save the generated images

### Model File
| Role | Filename |
|---|---|
| SDXL Checkpoint | `juggernautXL_ragnarokBy.safetensors` |

### KSampler Settings
| Parameter | Value |
|---|---|
| steps | 35 |
| cfg | 3.5 |
| sampler_name | dpmpp_2m_sde |
| scheduler | karras |
| denoise | 1.00 |
| seed | randomize (new seed each generation) |

### Latent Image Settings
| Parameter | Value |
|---|---|
| width | 832 |
| height | 1216 |
| batch_size | 10 |

### Notes on Text-to-Image Pipeline
- **JuggernautXL Ragnarok** is an SDXL fine-tune — use SDXL architecture (UNet, dual CLIP text encoders: CLIP-ViT-L + OpenCLIP-ViT-bigG)
- Negative prompt `"cartoon, deformed"` is hardcoded as default
- Batch size 10 generates 10 images per prompt — the user (or backend) picks the best one to pass to I2V
- Resolution 832x1216 is portrait orientation (note: I2V resizes to 640x640)
- CFG 3.5 is relatively low for SDXL — produces more natural, less over-saturated results
- DPM++ 2M SDE with Karras noise schedule is a high-quality stochastic sampler

## Image-to-Video Pipeline (from ComfyUI Wan 2.2 workflow)
Reimplemented as Python code in `backend/pipelines/image_to_video.py`:

### Nodes
1. **Load Image** — Receive the image generated by the text-to-image pipeline (PIL Image)
2. **Image to Video (Wan 2.2)** — Core generation node (details below)
3. **Save Video** — Encode frames to video file (format: auto, codec: auto)

### Wan 2.2 I2V Settings
| Parameter | Value |
|---|---|
| width | 640 |
| height | 640 |
| length (frames) | 81 |
| sampler_name | euler |
| enable_turbo_mode | true |

### Model Files (all .safetensors)
| Role | Filename |
|---|---|
| High noise model | `wan2.2_i2v_high_noise_14B_fp8_scaled.safetensors` |
| Low noise model | `wan2.2_i2v_low_noise_14B_fp8_scaled.safetensors` |
| CLIP (text encoder) | `umt5_xxl_fp8_e4m3fn_scaled.safetensors` |
| VAE | `wan_2.1_vae.safetensors` |
| High noise LoRA | `wan2.2_i2v_lightx2v_4steps_lora_v1_high_noise.safetensors` |
| Low noise LoRA | `wan2.2_i2v_lightx2v_4steps_lora_v1_low_noise.safetensors` |

### Pipeline Logic (pseudocode)
```
1. Load UMT5-XXL CLIP → encode motion/scene prompt into text embeddings
2. Load Wan 2.1 VAE
3. Load Wan 2.2 I2V high_noise model (14B, FP8) + apply high_noise LoRA (LightX2V 4-step)
4. Load Wan 2.2 I2V low_noise model (14B, FP8) + apply low_noise LoRA (LightX2V 4-step)
5. Encode start_image into latent via VAE
6. Create noise schedule (81 frames, 640x640)
7. Run denoising with euler sampler:
   - High noise steps use high_noise model+LoRA
   - Low noise steps use low_noise model+LoRA
   - Turbo mode enabled (fewer steps via LightX2V acceleration)
8. VAE decode latents → 81 frames
9. Encode frames to video file
```

### Notes on Wan 2.2 I2V Architecture
- Wan 2.2 uses a **dual-model approach**: separate models for high and low noise levels during denoising
- **LightX2V LoRAs** reduce the required denoising steps (4-step acceleration), making generation faster
- **Turbo mode** further optimizes the step schedule
- The text prompt describes the desired motion/scene (not the image content — that comes from the start image)
- FP8 quantized models are used for memory efficiency on consumer GPUs

## Development Notes
- When implementing pipelines, match the ComfyUI workflows exactly: same sampler, scheduler, CFG scale, steps, resolution
- Models use FP8 quantization — use `torch.float8_e4m3fn` where applicable, fall back to float16
- Keep pipeline code modular — each "node" is a function
- The I2V pipeline uses two separate 14B models (high/low noise) — manage GPU memory carefully, potentially offloading one while the other runs
- The motion prompt for I2V should describe camera movement and scene dynamics, not image content
- The frontend should show a loading state while generation is in progress (can take 30-120s for video)
- Video output: 81 frames at 640x640, saved as mp4
